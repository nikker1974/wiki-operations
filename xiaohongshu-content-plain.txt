想建个人知识库？你可能搞错了方向

你有没有这种感觉？Notion、飞书、Obsidian 里存了几百条笔记——但想找的时候永远翻不到。

最大的问题是：你的知识是"线性"的，但你的大脑是"网状"的。

[×] 树形目录 → 一个页面只能在一个文件夹
[×] 关键词搜索 → 搜得到靠人品，搜不到是常态
[×] AI 来读 → 大海捞针

「二宫和也是岚的成员 → 岚是杰尼斯的组合 → 杰尼斯在日本娱乐圈 → 日本音乐影响华语流行…」
这些关系是网，不是树。传统知识库没法表达。


那我为什么不用 gbrain？（12.9k stars）

gbrain 选择了 Postgres 路线：
[×] 要装 PostgreSQL + 配置中文分词
[×] 34 个 skill 全是英文提示词
[×] 单用户来说太重了

gbrain 是"团队级的大炮"，我想要的是一把"个人用的瑞士军刀"。


那 Karpathy 的 LLM-wiki 不是已经解决了？

Karpathy 提出了概念框架（Markdown + Git + AI 维护），方向完全正确，但没给具体实现：

[×] 没有页面格式规范
[×] 没有实体索引机制
[×] 没有可执行的 workflow

我做的 wiki-operations 就是把 LLM-wiki 概念落地成可执行的技能：

[OK] 双段式页面（可变摘要+不可变日志）
[OK] entities.json 实体索引
[OK] 完整的操作规范

装一行命令，Agent 读完就知道怎么干。


四个核心

[01] 网状结构 — 页面通过链接和索引互相关联，一条知识属于一张网
[02] AI 原生 — Agent 能直接读写，自动维护索引和日志
[03] 索引驱动 — 一个 JSON 记录所有人、事、工具的关系
[04] 双段式页面 — 上层写知识，下层记修改，互不干扰


一句话总结

你的知识是网，就别把它装进线性的盒子里。
